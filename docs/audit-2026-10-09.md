### Security posture (no high-confidence vulnerabilities found)

The Electron services layer is genuinely well-built:

- **[electron/services/job-websocket.ts](../electron/services/job-websocket.ts)** — timing-safe token comparison (`timingSafeEqual`), 5-second auth timeout, TLS **enforced** when binding beyond loopback, 56 MB message cap with 40 MB job-payload validation, strict `isPrintJob` shape/type guard (data-URL MIME allowlist, copies 1–100, finite numbers).
- **[electron/services/job-store.ts](../electron/services/job-store.ts)** — SQLite with WAL, `secure_delete`, parameterized queries only, status CHECK constraint, crash recovery that re-queues interrupted prints, `fileUrl` stripped from payloads after successful print (privacy).
- **[electron/services/print-service.ts](../electron/services/print-service.ts)** — SHA-256-derived staging filenames (no path traversal), MIME + size validation before writing, staged file removed in `finally`.
- **[electron/main.ts](../electron/main.ts)** — `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, single-instance lock, local-only crash dumps, token file written with mode `0o600`.
- Renderer: **no** `dangerouslySetInnerHTML`, `innerHTML`, `eval`, or `new Function` anywhere; `localStorage` config is runtime-validated on load; React escapes by default.

## 2. 🐛 Bugs (ordered by severity)

### BUG-001 — Fake demo orders ship to production POS (High) ✅ fixed

- **Location:** `src/shared/context/StudioContext.tsx:150` (`INITIAL_JOBS`), `StudioContext.tsx:469–471` (metric offsets)
- **Issue:** Three demo orders with Unsplash photos and real-looking phone numbers (`01799-887766`, etc.) load on **every app launch**. Daily metrics are hard-coded offsets: `todayPrintedCount = 127 + …`, `todayEarningsBDT = 4250 + …`. Demo counters also start with phantom stats (68/39/20 orders).
- **Impact:** A real shop's POS shows fabricated revenue and phantom orders forever. Approving any demo order on desktop **always fails** — `fileUrl` is an `https://` URL, which `print-service.ts:15` rejects as unsupported.
- **Fix:** Gate `INITIAL_JOBS` (and demo counter stats) behind a dev-only flag or seed only when the persisted queue is empty; compute metrics from real job data only.

### BUG-002 — Job ID / token-code collision (High) ✅ fixed

- **Location:** `src/shared/context/StudioContext.tsx:706–708`
- **Issue:** `jobNum = 127 + jobs.length` — but jobs auto-delete on the 15-minute countdown, so `jobs.length` shrinks and a new order can reuse an ID that already exists in SQLite. `enqueue()`'s `ON CONFLICT … WHERE status IN ('queued','failed')` won't overwrite a `completed` row, so the new job silently resolves to the **old** payload. Duplicate customer pickup codes (`tokenCode`) can also be issued.
- **Impact:** Wrong print content for a paid order; two customers with the same pickup token.
- **Fix:** Monotonic counter persisted in SQLite (or `crypto.randomUUID()`), and a separate collision-free token-code allocator.

### BUG-003 — New counter ID can duplicate an existing one (High) ✅ fixed

- **Location:** `src/features/print-agent/WindowsAgentView.tsx:141` (`handleCreateCounter`)
- **Issue:** `nextIndex = counters.length + 1` — delete CTR-02 from 3 counters, add one → `nextIndex = 3` → `CTR-03` already exists.
- **Impact:** Duplicate `id`s break React keys, counter filters, QR poster mapping, and `find()` lookups.
- **Fix:** Allocate the next unused ID (scan existing IDs) or use a random/UUID suffix.

### BUG-004 — Rejected jobs resurrect after reload (High) ✅ fixed

- **Location:** `src/shared/context/StudioContext.tsx:907` (`rejectJob`); `StudioContext.tsx:504` (status mapping)
- **Issue:** `rejectJob` only updates React state; the SQLite row stays `queued`, so on next launch `listQueue()` brings it back as approvable. Mirror problem: desktop queue status `failed` is mapped to `queued`/`approved` in `applyQueueJob`, so the `failed` state is never surfaced (only the `printError` text).
- **Impact:** Customers get prints the shopkeeper already rejected; failed prints look retryable-but-normal instead of failed.
- **Fix:** Persist rejection to the desktop queue (or delete the row), and map `failed` → a distinct renderer status shown in the UI.

### BUG-005 — `executePrint` decrements printers from a stale closure (Medium) ✅ fixed

- **Location:** `src/shared/context/StudioContext.tsx:884`
- **Issue:** Inside the 3.5 s `setTimeout`, `jobs.find(...)` reads the `jobs` array captured when `approveJob` ran — copies/paper decrements can use outdated values if the job was edited meanwhile.
- **Fix:** Use the functional `setJobs(prev => …)` form and derive the printer delta from `prev`, or read the job from state inside the updater.

### BUG-006 — Pending jobs show a dead "auto-delete" countdown (Medium) ✅ fixed

- **Location:** `src/shared/context/StudioContext.tsx:458–479`
- **Issue:** The 1 s ticker decrements `autoDeleteCountdownSeconds` on **queued** jobs too, so an order awaiting approval shows `00:00`/"deletes imminent" while the filter never removes it (only `completed`/`rejected` are deleted).
- **Impact:** Misleading, alarming countdown on a customer-facing counter.
- **Fix:** Only tick countdowns for statuses eligible for deletion.

### BUG-007 — Counter stats counted at creation, not completion (Low) ✅ fixed

- **Location:** `src/shared/context/StudioContext.tsx:836–846`
- **Issue:** `todayOrdersCount` / `todayEarningsBDT` increment when an order is *created*, even if it's later rejected — and start from phantom demo values (see BUG-001).
- **Fix:** Increment on completion (or decrement on reject), start from zero.

## 3. 🔒 Security notes (defense-in-depth — nothing critical)

These are hardening items, not exploitable vulnerabilities:

1. **No navigation lockdown in `electron/main.ts`** ✅ fixed — `setWindowOpenHandler` + a `will-navigate` guard keep the sandboxed renderer from being steered to a remote URL.
2. **Preview iframes lack `sandbox`** ✅ fixed — `src/features/shop-pos/OrderCardModal.tsx:380` and `src/features/customer-pwa/CustomerPwaView.tsx:677` now render `job.fileUrl` in `<iframe sandbox="">` (verified previews still render).
3. **`desktop:queue:save-job` validates only `id`** ✅ fixed — the IPC path reuses the exported `isPrintJob()` guard for full parity with the WebSocket path.
4. **Google Fonts CDN in `index.html:14`** — the packaged desktop app depends on internet for correct typography; self-host the three fonts (Hind Siliguri, Plus Jakarta Sans, JetBrains Mono) for offline shops.
5. **README-documented residual risks** (accepted): plaintext token file, no token rotation UI, shared bearer token with no per-counter identity.

## 4. 🎨 Frontend UI

### Dead CSS classes — verified against built `dist/assets/*.css` (none emitted)

- ✅ **fixed** — **`hover:bg-slate-750`, `bg-slate-850`, `border-slate-850`** — these shades don't exist in Tailwind's palette. 11 occurrences across `ShopPosView.tsx:185/199`, `CounterPosterModal.tsx:104/113/125`, `WindowsAgentView.tsx:788/950/959/1014/1043/1068`. **Hover states on counter filters, poster tabs, and agent buttons silently do nothing.**
- ✅ **fixed** — **`animate-in fade-in` / `slide-in-from-bottom-5` / `zoom-in-95`** — these come from the `tailwindcss-animate` plugin, which is **not installed** (Tailwind v4 has no `animate-in` utility). Every modal and the order toast **pops in with zero animation** despite clear intent.
- **Fix:** add `tw-animate-css` (Tailwind v4 equivalent) or swap to core transition/keyframe utilities; replace `slate-750/850` with real shades (`slate-700`/`slate-800`/`slate-900`).

### Accessibility

- No `role="dialog"` / `aria-modal` / **Escape-to-close / focus trap** on the four fixed overlays (`OrderCardModal`, `CounterPosterModal`, `WindowsExePackageModal`, agent inner modals).
- Order-table rows are click-to-open `<tr>`s with no keyboard path (`tabIndex` + Enter handler).
- The new-order toast has no `aria-live="polite"` — screen readers never announce incoming orders.
- `text-[11px] text-slate-500` on `bg-slate-900` is below AA contrast for small text — bump to `slate-400`.
- No `prefers-reduced-motion` handling.

### Other UI / product polish

- Printer name rendered as `split(' ')[0] + ' ' + split(' ')[1]` → shows "Epson EcoTank" and drops the model ("L805").
- Shop settings auto-approve list hard-codes 5 services (`ShopPosView.tsx:506`) — owner-created **custom services can't be toggled there**.
- `URL.createObjectURL` in the PWA upload path (`CustomerPwaView.tsx:197`) is never revoked — slow memory leak on repeat uploads.
- No favicon; footer claims "Driver Abstraction Layer Active" unconditionally.
- `updatePricing`'s key mapping covers only the 5 built-in services — pricing edits for custom services silently do nothing.
